## v0.7.5 - Unreleased

Reading-time preparation, optional prose cleanup, and broader Library imports. Application version: **0.7.5**.

- **Revise continuity** lets the author request one proposed alternative of an unaccepted draft using its exact saved evidence and profile. Original and proposal remain separate until Keep; full inputs and feedback are inspectable. Budget refusal, cancellation/retry, character scope and archive v36 validation preserve source and acceptance boundaries. Automatic checking remains experimental. The [consolidation audit](narrative-reliability-audit.md) records useful targeted corrections, unchanged clean controls and remaining unsupported-history failures.

- **Story memory > Check earlier evidence before writing** adds optional prewriting recall, off by default: one bounded preparation call per writer candidate, up to two searches and eight exact passages from its frozen accepted path, within the original context allowance. Failed preparation visibly falls back to the original context. Preparation output cannot become story prose or accepted memory.
- Draft receipts preserve per-candidate final inputs, search decisions, displaced optional passages, preparation usage and timing. Completed preparation is reused on retry and Try another; cancellation does not start the writer. Preview and comparison screens distinguish shared initial inputs from final candidate evidence. Archive checks validate scope, source bytes, selection and replay, including original identities after restore.
- **Use tentative relationship links** adds bounded source-backed event, intention, testimony, knowledge-claim and relationship extraction. Prepare existing passages in **Writing tools > Story memory > Relationship links**, inspect exact inputs/quotes, and stop or explicitly retry requests. The separate automatic opt-in applies only after new prose is accepted and requires verified background interruption. Source exclusions and branch changes invalidate dependent links; extraction never changes accepted facts or plans. Archive format 34 and recall receipt version 4 preserve requests, attempts and frozen aids.
- Relationship integration passed 102 affected backend tests and controlled desktop/mobile browser checks. The final seven-case live comparison on LM Studio's loaded Ateron Gemma model supplied 12/19 required passages with baseline recall, 17/19 with prewriting and 19/19 with live grounded links, at equal input allowances. Linked prose remembered the successful sibling's receipt, but still omitted events and invented unsupported history, including a regression on the earlier fork. Calls, latency, interventions and mixed prose findings are recorded in [evaluation details](enhanced-story-memory-evaluation.md).
- Query and relationship preparation accept one outer JSON code fence. A supplied original-source/node ID resolves only when it identifies one supplied excerpt; canonical IDs and exact unique quote checks remain enforced. Invalid schema values and ambiguous aliases still fail. All 56 affected recall, relationship, evaluation, group and semantic tests passed after the live follow-up.
- The full backend integration run had 1,230 passes and three stale assertions (two archive-version checks and one older import-error message). After correction and completed-receipt replay hardening, all 61 focused follow-up checks passed; the full suite was not repeated. - Prewriting recall follows accepted plan evidence across earlier edits, and uses accepted scene descriptions or enabled reviewed summaries to fetch exact originals. Writer and author see complete or partial coverage of the recorded group. Exclusions apply before discovery; coverage notes and originals share the existing input allowance. Old version 1 and 2 requests retain their packing behavior.
- **Also search by meaning** adds optional semantic recall through an explicitly configured **Embedding model ID** on a Local, OpenAI or compatible writer connection. Independent keyword and semantic candidate lists combine by reciprocal rank before group selection. Embeddings are disposable and keyed by source bytes and saved profile configuration. Each writing request can prepare at most 64 new source chunks in four batches, then make one query-embedding request; the semantic step has a 30-second ceiling. Missing configuration, incomplete cache coverage, invalid responses, unsupported sizes or timeouts visibly retain keyword search.
- **Embedding input format** supports Nomic's separate document/query search prefixes with an isolated cache identity. Plain text remains the default and preserves legacy identities; full source chunks survive prefixing. Profile persistence, semantic retry/archive behavior, provider bounds and desktop/mobile settings were verified.
- [Narrative reliability consolidation](narrative-reliability-evaluation.md) adds frozen paired trials (132 drafts, two local writers), 16 bounded checker trials, and public-domain retrieval/scale benchmarks including a 104,506-word collection. Guidance and checking remain experimental: neither reliably prevents unsupported history. Prefix-correct live semantic fusion supplied 22/34 required groups in final packets versus 20/34 lexical, with 28/34 present among fused candidates; context packing and manuscript continuation remain open work. The production writer prompt is unchanged.
- [Packing follow-up](narrative-reliability-followup.md) fixes eviction of query matches already supplied to the writer. Recall v5 retains those matches while adding evidence or coverage notes; previous request versions preserve their original bytes and algorithm. Archive v35 supports the new behavior without upgrading historical request contents. Frozen replay improves final evidence coverage to 27/34 lexical and 28/34 fused, at unchanged limits; fourteen historical live receipts still replay exactly. Coherent manuscript/fork writing and further reading-note/thinking comparisons are documented separately from retrieval scores.

- **Library > Import file** recognizes Pygmalion and Backyard/Faraday legacy characters, plus standalone portable, SillyTavern, NovelAI (versions 3–6), Agnai and RisuAI (version-1 export) lorebooks. JSON and `.lorebook` dialects are identified from their fields; supported native character JSON can also be carried in PNG cards. Existing Character Card, Markdown and SGC conversion receipts are unchanged.
- Native imports show a field-mapping preview, retain exact original bytes and unknown metadata, and publish only reviewed character fields or Canon overviews. Preserved entry texts can be added through **Edit Canon entries > Bring in preserved entries**; plain keyword and always-on proposals start off. Foreign regex, secondary logic, timing, ordering and priority fields remain for review rather than being treated as equivalent rules. Conversion uses no model, runs no scripts, and fetches no media links.
- The import viewer keeps source-document controls usable at enlarged interface sizes. `.charx` / `.byaf` containers, DOCX/PDF/EPUB documents, and chat transcripts remain future work. The adapter and preservation approach was informed by [Hoplight](https://github.com/Coneja-Chibi/Hoplight/tree/0453346d5f2a1b5b921f2fb67d6eabbb2c5e0dca); its source is not a runtime dependency.

- **Cleanup timing > While I read** makes a completed original immediately available for Keep or further writing. Cleanup runs separately, offers an explicit wording choice, and never silently swaps the text being read. Accepting freezes the selected version; typing, new writing, Stop, and turning cleanup off interrupt optional work.
- Shared inference scheduling prioritizes writing and required assessment over helpers, reading-time cleanup, and automatic summary maintenance. Local connections share one slot by default; explicit resource groups support independently provisioned hardware. Cancelled waiters are removed, and an active background lease stays held until server termination is acknowledged.
- LM Studio native HTTP connections with no API authentication and model-default reasoning can explicitly verify interruption using two synthetic requests. Verification lasts 30 minutes per app session and saved configuration. Every admitted background request still requires terminal acknowledgement; an unconfirmed stop blocks the resource until an explicit server-restart/reset check. Other connections retain cleanup before ready and manually requested model helpers.
- A bounded worker warms the existing content-addressed chunk and lexical indexes for newly committed prose. It coalesces pending work and yields to foreground preparation. Retrieval scope, branch decisions, accepted memory, and plans remain authoritative; cache misses use the existing path.
- Observed timings distinguish context preparation, provider queueing, first text, writing, draft readiness, and cleanup. Archive format **33** preserves the timing mode; restore clears pending work, disables automation, and never resends cleanup.

- **Writing tools > Phrase check** finds recurring sequences of 3–8 words in accepted prose on the selected path. Checks run locally on request, with no model calls. Choose the latest 20 or 100 prose passages, or the path within the displayed size limits.
- Observations show counts, exact highlighted excerpts, and links back to their original passages. Capitalization, spacing, and apostrophe variants are normalized while source text and offsets remain intact. Overlapping fragments are grouped and phrases made entirely of common words are suppressed.
- Editable templates suggest varying wording or considering a cut. Copy guidance to use when you choose; checks do not rewrite prose or change writer instructions.
- Phrase checks start off. Dismiss a particular observation, mark wording intentional for future checks, and restore either choice. These preferences belong to this browser and path; they are not inherited by another branch or included in story archives.
- This first slice checks wording only. Semantic repetition, stalled exchanges, scene-pattern analysis, and homeostatic retrieval remain future work. Checks cover at most 200,000 characters or 40,000 words in complete passages and display up to 30 groups, with explicit coverage limits.

- **Writing tools > Automated cleanup** starts off on each path. After a writer finishes, deterministic phrase detection can trigger at most one polishing call with the saved writer profile. Continue story, send-and-continue, beat-assessed requests, and comparisons share the same stage; no cleanup calls occur for unflagged or protected wording.
- Cleanup returns up to 12 replacements for exact flagged spans. Code rejects overlapping edits, invalid output, added sentences, and edits outside those spans. Complete original prose stays saved; compare versions and choose which wording to keep before accepting the draft. Meaning and voice still need author review.
- Intentional and dismissed phrase choices are frozen with the request. Enabled author-memory motifs protect matching wording; numbers and capitalized content words are conservatively excluded. Changes to the path, draft, author-memory decisions, or opt-in version invalidate pending results. Turning off or stopping cleanup durably preserves the original even if a provider returns late.
- Durable writing receipts, explicit writer retries, cleanup cancellation, startup recovery, and independent usage records prevent automatic resend of cleanup. Cleanup failures leave a completed, acceptable original. Archives preserve originals, replacements, evidence, and captured choices; restores disable automation and recover interrupted cleanup without model calls.
