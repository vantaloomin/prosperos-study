# Enhanced Story Memory implementation goal

Build on v0.7.5 in `codex/v0.7.5-memory`, preserving the existing reading-time preparation work. This is an implementation goal, not a release authorization.

**Complete — 2026-09-19.** All five stages are implemented and evaluated. Live linked recall supplied 19/19 required permitted passages versus 12/19 for baseline, but prose still omitted events and invented unsupported history. See the completion audit and [evaluation](enhanced-story-memory-evaluation.md) for the measured limits. No release or publication is part of this goal.

## Intended outcome

Ordinary writing should find the source passages needed to understand a narrative relationship, including a promise, a handoff, and a later failed delivery. Finding one related passage is not evidence that the whole relationship was retrieved. The successful-delivery sibling path must remain separate.

Accepted prose, pinned Canon, explicit plans, participant commitments, and author decisions remain authoritative. Derived search aids cannot accept events, finish plans, merge branches, resolve conflicting testimony, or grant a character knowledge.

## Stages

- [x] 1. Opt-in bounded prewriting recall: one preparation call per candidate, at most two search queries and eight exact-source passages, followed by the writer. Use the frozen permitted archive, retain the existing input allowance, record source and budget decisions, and fall back visibly to deterministic context. Integrate settings, preview disclosure, progress, cancellation, explicit retry, recovery, and archive round trips. Character-lens writing must never gain access to the ordinary writer archive.
- [x] 2. Budgeted evidence groups: expand accepted plan relationships first, then tentative sourced links. Fetch missing originals; preserve chronological order, visited/count limits, source digests, and explicit incomplete coverage. Searchable scene/summary descriptions resolve to originals without replacing granular retrieval. Do not restore automatic adjacent-passage expansion.
- [x] 3. Independent lexical and optional semantic discovery: search both candidate sets independently, combine by rank, deduplicate, then apply group coverage and budget selection. Embeddings are disposable, versioned by source digest and model configuration. Keep a complete lexical fallback.
- [x] 4. Optional incremental relationship annotations: extract only new/changed permitted sources, quote supporting spans, distinguish assertions from knowledge/testimony, invalidate stale derivations, and schedule behind foreground work. These are discovery aids, not accepted facts and not mandatory author curation.
- [x] 5. Narrative evaluation: compare against the current writer at equal input allowances, covering failed versus successful delivery, changed names/pronouns, withdrawn promises, conflicting testimony, exclusions, and branch forks.

## Invariants

- Apply branch ancestry, exclusions, source versions, and character scope before discovery.
- Preserve exact final provider input and retrieval receipts independently for each candidate; completed preparation is reused on explicit retry.
- A cancelled or interrupted operation does not silently resend. Preparation output is never displayed or accepted as prose.
- Preparation has bounded output and time; malformed, unavailable, or oversized preparation uses the original deterministic packet with a visible reason.
- Source passages are data, not instructions. New retrieval must fit the existing profile input allowance and overhead margin.
- Keep existing foreground priority, owned-provider cancellation, cleanup, and first-prose timing behavior.
- Archive and restore preserve frozen input bytes and validate provenance rather than silently rebuilding inputs from the current path.

## Verification and reporting

Use focused tests for changed contracts, then frontend lint/build when UI changes. Exercise the ordinary generation endpoint, retry/cancel/recovery, context preview, and archive import/export. Report deterministic evidence coverage separately from live model narrative quality, calls, latency, and author interventions. No unmeasured improvement claims.

## Stage 1 implementation and evidence — 2026-09-19

The opt-in is **Story setup > Writing preferences > Story memory > Check earlier evidence before writing**. Its setting defaults off. `server/memory/writer_recall*.py` freezes eligible accepted chunks, requests a bounded JSON search plan, independently searches each query with the existing lexical scorer, interleaves/deduplicates at most eight hits, and packs exact excerpts. Search scope excludes blocked chunks before ranking. A queried original can replace its own reviewed summary by matching source, range, and digest.

One preparation request uses the frozen writer profile with an output ceiling of 512 tokens and a timeout ceiling of 60 seconds, also bounded by the profile's own limits. Output is limited to 4,096 characters; each of at most two queries is limited to 1,000 characters. New evidence has a ceiling of 1,600 estimated tokens or 20% of the existing input allowance after overhead, whichever is smaller. Optional older excerpts or older whole passages can be displaced; the last three already-selected whole contributions, all author notes, plans, and Canon remain protected. Rejected insertions do not remove existing context. These are starting limits, not measured optimal settings.

`candidate.usage.writer_recall` and preserved attempt records retain the preparation output, profile configuration, usage, elapsed time, source digest, decisions, and exact final writer input. Retry and Try another reuse a completed or fallback preparation. Interrupted preparation waits for an explicit retry. The preparation response does not set first-prose timing or appear as candidate prose. Archive validation checks both the frozen eligible archive and the final candidate input, including restored source identities and surviving summary bindings. No new database table or migration is needed for this versioned optional receipt.

## Stage 3 implementation and evidence — 2026-09-19

**Also search by meaning** defaults off and requires an explicitly configured **Embedding model ID** on each candidate's Local, OpenAI or compatible writer profile. Requests use the connection's embeddings endpoint; native LM Studio writer URLs resolve to its compatible `/v1/embeddings` endpoint. The writing model is never silently substituted. Profile changes start a new cache namespace; cache keys include exact source digest, saved profile identity/version, endpoint, model and embedding algorithm. Cache data is disposable and does not control source eligibility.

Each semantic search considers all frozen permitted prose independently of lexical results. Both query lists retain up to eight hits; reciprocal-rank fusion uses offset 60, then existing group and budget selection applies. Semantic cosine starts at 0.2; this threshold and the rank constant are uncalibrated starting values. Before fusion, all permitted sources must have usable embeddings; incomplete cache coverage falls back to the full lexical path. Warming is bounded to 64 new chunks in batches of 16, plus one request embedding at most two queries. Total semantic time is bounded to 30 seconds or the profile timeout, whichever is smaller. Search is capped at 4,096 sources, two million vector components, 8,192 dimensions per vector and four MiB per provider response. Finite nonzero vectors, batch indexes, consistent dimensions and model identities are checked. CPU ranking and cache I/O run outside the event loop.

Embedding requests use the foreground request scheduler. They are explicitly prohibited in automatic background work because this endpoint has no verified background termination protocol. Cancellation aborts preparation and never starts the writer. Version 3 recall archives freeze the opt-in and limits; version 1 and 2 packing remains available. Candidate receipts retain model identity, query rankings/source digests, cache counts, calls, provider usage, time and fallback. Archive validation checks semantic scope and bounds and replays final selection using the saved derived rankings; it does not independently reproduce a remote model's similarity judgments. Restoring or retrying a completed preparation makes no new embedding request.

Validation: **83 affected backend tests passed**, including **14 new semantic tests**. The run covered semantic recall, prewriting recall, evidence groups, provider transport, profiles, request scheduling, context contracts and generation recovery. It verified non-keyword semantic discovery, invalid responses, bounded incremental cache warming, source/profile invalidation, visible fallback, cancellation before prose, retry and archive restore/re-export with identical receipts, and rejection of an out-of-scope semantic result. Two existing dependency deprecation warnings remain. Ruff, ESLint, TypeScript and production build passed; `git diff --check` reported no whitespace errors.

## Stages 2 and 4 completion and evidence — 2026-09-19

**Use tentative relationship links** defaults off. **Writing tools > Story memory > Relationship links** can prepare up to four previously unrequested source chunks using the Story's resolved writer profile. Each request has a maximum of eight original chunks, four returned annotations and four exact quotations per annotation, with 1,200 output tokens and 60 seconds as ceilings. The input must fit the saved profile. Empty annotations are valid. Exact quotations must resolve uniquely inside supplied chunks and every annotation must cite its target. The schema separates events, intentions, testimony, knowledge claims and relationship interpretations; exact grounding does not prove that an interpretation is correct.

Earlier lexical hits, up to two recent extraction-context chunks, and earlier sourced intentions/relationships can inform extraction. This does not add general neighboring passages to writer recall. Tentative descriptions locate groups; the writer receives their original evidence and neutral tentative labels, not model-authored assertions as accepted facts. All input chunks are dependencies: changed branches or exclusions invalidate the whole derivation. Shared ancestors can reuse eligible work; unrelated sibling outcomes cannot. Character-lens and scene requests still do not receive ordinary writer recall.

**Prepare links after accepted prose** is a separate opt-in. Its acceptance-time check excludes prose accepted while the switch was off, including notifications still waiting for debounce. Notifications coalesce within a bounded queue. Only a connection with verified background interruption can make automatic requests; other connections support explicit preparation. Restored requests and imported nodes do not automatically replay. Newly accepted prose after restore can prepare normally. Foreground work interrupts background extraction, and a verified native request retains its shared-resource lease until stop acknowledgement. OpenRouter automatic interruption is not verified; manual OpenRouter preparation remains available.

Durable request and attempt receipts retain frozen inputs, raw output, result, usage, cancellation and errors. Failed, stopped and interrupted targets require an explicit retry. App recovery never resends them automatically. Branch changes, story archival, disabling the writer or the opt-in, and source exclusion stop ineligible active work. Controls expose exact inputs/quotes, stop and retry. There is no acceptance action for these search aids and no change to accepted plans or character knowledge.

Recall archive version 4 freezes eligible annotation aids. Story archive format 34 adds relationship requests and attempts; older formats migrate with empty tables, and recall versions 1–3 keep their existing behavior. Import checks canonical source bytes, input allowance, quotation positions, saved profile, request fingerprint and derived result. Frozen receipt identity survives restore/re-export, while future requests can use remapped eligible originals.

Validation: **102 affected backend tests passed**, including seven relationship tests. They cover incremental preparation, writer integration, exact/ambiguous grounding, successful siblings, exclusions, disabling, stop/retry, preserved attempts, crash recovery without resend, idempotent request replay, native stop acknowledgement, and archive restore/re-export/tamper rejection. The first interruption test exposed acceptance-time opt-in leakage; after the fix it passed with the affected suite. Two existing dependency deprecation warnings remain. Ruff, ESLint, TypeScript and the production build passed.

Bundled Playwright exercised saved opt-ins, explicit preparation, stop and retry, quotation/input inspection, context-preview disclosure and a tentative-group writer receipt on desktop 1440×1000 and mobile 390×844. All five screenshots were inspected, with zero measured page horizontal overflow and no console warnings/errors, page errors or framework overlay. Two initial selector mismatches were corrected before the passing flow. This used disposable data and a controlled provider on port 18768; it did not call LM Studio or use personal prose.

## Stage 5 completion — 2026-09-19

The reproducible controlled comparison in `scripts/relationship_evaluation.py` exercises the ordinary generation endpoint for seven cases and three variants at the same 4,096-token context / 512-token output settings. It compares baseline retrieval, prewriting recall, and prewriting recall with supplied grounded links. Evidence coverage was respectively **10/19**, **17/19** and **19/19** required permitted passages; complete case coverage was **2/7**, **5/7** and **7/7**. No excluded or sibling-only passage appeared, and every packet stayed within the same 3,584-token input allowance, including overhead. These are controlled retrieval results, not live annotation reliability or narrative quality. See [the evaluation report](enhanced-story-memory-evaluation.md) for per-case coverage, calls, interventions, latency scope and limitations.

The initially requested **Z.ai GLM 5.3 Flash on OpenRouter** probe returned **HTTP 401** in **0.656 seconds**, producing no output. The credential blocker persisted across three goal turns and the goal was then blocked. The user subsequently relaunched and authorized LM Studio, allowing work to resume without changing the original objective or personal profiles.

The completed seven-case live comparison used the already-loaded `ateron_gemma-4-novelist-eclipse-31b` instance, native protocol, temperature 0, reasoning off and the same 4,096-context / 512-output configuration in every variant. Neutral synthetic Story titles and directed prose removed outcome labels and roleplay restrictions from the final fixture. All 63 responses reported the selected model. Evidence coverage was **12/19 baseline**, **17/19 prewriting**, and **19/19 prewriting plus live links**, with complete cases **2/7**, **5/7**, and **7/7**. Every final input fit its 3,584-token allowance, zero forbidden originals appeared, and accepted plans remained empty.

All 14 query preparations completed. Of 28 annotation responses, 27 passed validation and produced 29 items. One changed-name response supplied blank relationship types and was rejected without a retry or weakened validation. The 21 drafts received a qualitative review against accepted source history and final inputs; it was performed by the implementation agent with variant identities visible, not as a blind study. Linked prose remembered the successful sibling's receipt, but omitted some retrieved outcomes/testimony, invented the excluded handoff, and invented a resolved outcome on the earlier fork. The latter is a narrative regression in this sample, despite correct source scope. No overall prose-quality improvement is claimed.

The final comparison made 63 calls (28 annotation, 14 query, 21 writer), consuming 121,706 provider-reported input tokens and 7,742 output tokens. Seven explicit batch actions required zero per-link curation, query edits or retries. Median continuation time was 6.217 seconds baseline, 8.822 with prewriting and 8.861 with prepared links; initial four-request preparation had median 19.219 seconds. These are measured local pipeline times, with setup reported separately. The [evaluation report](enhanced-story-memory-evaluation.md) documents per-case behavior, ranges, prior exploratory runs, request artifacts and unmeasured limits.

Live testing exposed bounded output-compatibility issues. A single outer JSON fence is now accepted for query and relationship responses. Supplied original-source/node IDs resolve only when they identify exactly one supplied excerpt; stored citations use canonical chunk IDs and unchanged exact unique quotation checks. Multiple documents, ambiguous aliases, unsupported schema values and ungrounded quotations still fail. Existing completed and fallback receipts remain frozen.
